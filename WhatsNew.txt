二、我这边有、上游没有
================================================================================

1. AI 接入层（差异最大的一块）
   上游：2 种协议（openai / claude）、单套配置、没有采样参数、不显示思维链。
   现在：
   - 4 种协议：openai chat / openai responses / anthropic / gemini 原生。
   - 多配置档案：增删改名、切换、服务端持久化（app_settings.providers）。
     切换档案时 api_key / base_url / model / type 一并镜像到扁平字段，
     旧路由不用改就能继续工作。
   - 拉取模型列表（POST /api/ai/models），可从列表选而不用手打模型名。
   - 采样参数：温度、Top P，按协议 clamp（openai 2.0，其余 1.0）；
     另有 top_p 支持性探针（POST /api/ai/probe-sampling），探针判定不支持后
     旧档案里残留的 top_p 也不再发送（否则必然 400）。
   - HTTP 超时（全局，默认 90 秒，可按秒改）。
   - 上下文窗口与最大输出分开设，各自独立（上游只有一个 maxOutputTokens）。
   - 思维链：折叠面板 + 流式展示；档位（关闭/简短/标准/沉思/默认）；
     语言（跟随模型默认 / 用写作语言思考）。上游完全不显示思维链。

2. 上下文治理
   上游：把项目现状和章节原文直接拼进去，没有预算概念。
   现在：
   - Token 预算裁剪：预算 = 上下文窗口 − 最大输出 − 4000，下限 2000；
     超预算时按优先级丢弃低价值段落，而不是让请求直接 400。
   - 「每章理想字数」可设，注入提示词作为篇幅目标；上游只有三段式
     （短篇/中篇/长篇），不能填具体字数。
   - 写作语言自动判定（见第四节 1）。

3. 数据安全与可回滚
   上游：没有任何快照或备份机制。
   现在：
   - 项目里程碑快照：复制整库 + 还原 + 还原前自动备份；快照目录按项目名派生。
   - 存储位置迁移：设置里可改书库位置，带迁移确认、进度、失败回滚与重启提示。
   - 伏笔状态变化流水（foreshadow_changes 表）。
   - 关系变化快照（relation_snapshots 表）。

4. 写作流水线
   上游：没有。
   现在：
   - 章节定稿自动总结：一章定稿后异步做四件事 —— 生成章节摘要、提取叙事记忆、
     记录人物关系变化、推进伏笔状态。fire-and-forget、内存去重队列、
     启动时补跑、无 key 时保持 pending 而不是失败。
   - 工具循环健壮性四件套：
     截断自动续写（上限 3 次，输出被 max_tokens 截断时不收尾，继续要下一段）、
     required 参数拦截（缺 chapter_num 之类的调用不执行，把原因写回对话）、
     空响应催促（整轮被思考吃光时改催促语，要求带全参数分段写）、
     content_mode=replace/append（长章节分段写，不用一次吐完）。
   - 多卷同号保护：按 (volume_id, num) 定位，两卷同号时报错而不是误改别的卷。

5. 交互与结构
   - 消息编辑 / 删除 / 重试（上游只能删整个会话）。编辑只落库，重试才重跑。
   - 章节编号方式可选：每卷从 1 开始 / 全书连续。
   - 侧栏条目由数据库驱动（sidebar_items 表），不是前端写死。
   - 仪表盘可增删创作类型，且决定科幻设定页是否出现。
   - 编辑器撤销 / 重做（从上游移植，已对齐）。
   - 自动保存间隔可调：15 / 30 / 60 / 120 秒，或关闭。

6. 导入旧稿（本轮新增）
   上游也有导入，但实现路线不同，见第四节 2。

四、同一需求、两种实现（重点）
================================================================================

1. 写作语言

   上游做法（显式选择）：
   - 建项目时从 8 种语言里选一种（NewProjectDialog.tsx:341-348）。
   - 存进 project_meta.language。
   - 拼提示词时 languageName(meta.language) 注进「项目现状」
     （server/prompts/context.js:71）。
   - 语言表在 server/languages.js，除名字外还带 perChapterTokens，
     用来给 AI 导入分批算输出预算。

   本构建做法（自动判定）：
   - 没有这个字段，界面上也没有语言选择项。
   - 每次拼提示词时现算（server/lang-detect.js → context.js:104-105）：
       第一优先：最近几条 AI 对话里用户自己说的话
       第二优先：最近更新过的章节正文
       第三优先：界面语言（app_settings.ui_language）
   - 判定靠 Unicode 区段字符占比（汉字/假名/谚文/西里尔/拉丁），主导率阈值 0.5，
     最少 12 字；拉丁字母再按虚词与变音符区分英/法/西；繁简按标记字集判断。
   - 结果只注入一行「写作语言: X」。

   影响：
   - 好处：换语言不用重建项目；先用中文写、后来改用英文跟 AI 说话，正文会跟着变；
     八个语言包的界面语言本身就是兜底值。
   - 代价：无法锁定。同一个项目里若两种语言混着说过话，判定会跟着最近的消息漂。
     想稳住只能靠「最近一章正文」这一级，即先把正文写成目标语言。
   - 实测：8 种语言单元测试 10/10 判对；空项目 → 简体中文（来源 ui）；
     插入一句英文用户消息 → English（来源 chat）。

2. 导入旧稿

   上游做法：
   - /projects/import 收原始文本或文件，/projects/import-ai 做结构化。
   - 切不动的部分交给模型：分章、抽标题、抽卷，按章发请求。
   - 花 token，但能处理没有标题行的纯文本书。

   本构建做法：
   - 只有 /projects/import 一个接口，纯规则，零 token。
   - TXT：用 titles.js 的卷/章正则切分；标题行必须短且不以句末标点结尾。
     找不到任何标题时按长度在空行处兜底切分。
   - EPUB：jszip 读 META-INF/container.xml → OPF → spine，逐个 XHTML 转文本，
     正文首行与章名相同时剥掉首行。
   - 上限：600 万字 / 5000 章 / 30 MB 文件。
   - 导入后章节状态设为 accepted，算一次总字数，生成一张初始快照。
   - 界面：新建项目弹窗两个标签页（空白项目 / 导入旧稿），支持拖拽，
     按文件名自动填项目名，TXT 自动试 UTF-8 / GBK / Big5 解码。

   影响：结构化程度不如上游，遇到排版混乱的 TXT 会切得粗糙；好处是不花钱、
   不依赖模型、断网也能导。

3. 项目名允许任意字符

   上游做法：文件名不再等于项目名 —— 库文件叫 <randomUUID>.mythpen.db，
   显示名与 file_path 存进 recent_projects 注册表，所以 / : ? 这些字符随便填。

   本构建（本轮改成同构）：
   - allocateProjectFilePath() → <PROJECTS_DIR>/<randomUUID>.mythpen.db。
   - 显示名 + file_path 存注册表；读库时先查注册表，查不到再回退旧布局
     <名称>.mythpen.db，旧项目照常能开。
   - 封面 / 导出 / 快照子目录走 projectDirKey()：安全名原样用，
     含 \ / : * ? " < > | 的换成 slug-hash8，避免出现嵌套路径。
   - 仍保留的校验：不能为空、不能超过 200 字、不能是 . 或 ..、
     不能含换行与制表符等控制字符。其余字符不再拦截。
   - 实测：项目名「测试/斜杠?问号:书名」建项目、建章、建快照全通，
     快照目录为「测试_斜杠_问号_书名-dfcf6738」。

  （api_key / api_base_url / api_model / ui_language）。
- 死文案 92 条：中文与英文各 728 → 637，其余六种语言各 580 → 551。
  大头是 relations.type* 18 条（关系类型早已是自由输入）、settings.* 17 条

  同时把文案从「每 N 秒自动保存」改成「编辑停顿 N 秒后自动保存」——

六、本轮修掉的缺陷
================================================================================

1. 章节列表跨卷错序
   GET /:project/chapters 原来是 ORDER BY c.num，分卷各自从 1 编号时
   会排成「卷1第1章、卷2第1章、卷3第1章、卷2第2章」。
   改成 ORDER BY v.sort_order, c.num。

2. 导入后多出一个空卷
   卷前那段文字被收成「前言」独占一卷，紧接着的「第一卷」标记又开一卷。
   改成当前卷只有前言时直接把卷名给它。

3. EPUB 正文重复标题
   正文首行与提取出的章名相同时，正文里会再出现一遍章名。已剥掉首行。

4. 死文案审计方法本身出过偏差
   第一版把 pages.phaseIdea…phaseExport 判成死键，实际它们由
   t(`pages.${PHASE_LABELS[x].key}`) 拼出来。判死之前必须先把所有
   模板拼接的 t(`…${ 找一遍，否则会误删还在用的文案。
